# 光盘小分队用户验收记录

更新时间：2026-06-06

## 验收视角

这个小程序的核心用户不是开发者，也不是电商买家，而是一个临到饭点才开始犯难的家庭成员。用户最在意的是：

- 快速决定这一餐吃什么。
- 能把菜加入菜单，并知道下一步该做什么。
- 确认后能照着菜篮子买菜。
- 家人可以一起参与，不要出现“看起来同步了、实际没同步”的假状态。
- 文案要像生活工具，不能像后台系统或接口调试页面。

## 主流程验收

1. 首页随机一餐
   - 用户可以选择随机几道菜，默认 3 道。
   - 随机结果可以加入菜单。
   - 已修复：同一套推荐重复点击不会无声叠加份数。

2. 选菜页
   - 左侧分类、右侧菜品列表符合常见点餐体验。
   - 已修复：创建/加入家庭后，选菜页优先显示家庭成员，而不是只显示本机默认成员。

3. 我的菜单
   - 用户可以调整份数、删除菜品、进入确认菜单。
   - 已修复：确认页收集菜品时兼容布尔选择状态，避免“明明选了菜，确认页却为空”。
   - 已修复：去掉“库存不足”“商品规格”等电商语境文案。
   - 已修复：异常数据下点选或改份数不会直接卡住。

4. 确认菜单
   - 用户确认后菜单进入历史。
   - 已修复：确认成功后清空当前菜单，避免用户重复确认同一餐。
   - 已修复：确认后进入菜篮子，会使用刚确认的那份菜单。

5. 菜篮子
   - 用户可以按备料勾选已买项。
   - 已修复：确认新菜单或复用历史菜单时，会清掉上一餐的已买勾选，避免漏买。

6. 我的家庭
   - 用户可以添加手机号、创建家庭、加入家庭。
   - 已修复：不再展示 `user_xxx`、固定身份、脱敏等工程语言。
   - 已修复：如果旧家庭已经不存在，会清掉本地旧缓存，避免持续显示假状态。

7. 自定义菜
   - 用户可以新增和编辑家里常吃的菜。
   - 已修复：编辑步骤时插入/删除行，步骤图会跟随相同步骤，不再按下标错配。

8. 提个想法
   - 当前只是本机记录。
   - 已修复：文案不再写“发给我们”，避免用户误以为后台已经收到。

## Subagent 发现的问题

本轮使用两个 subagent 做只读审查：

- UX 审查：从普通家庭用户角度挑出流程断链、文案误导、家庭同步落差。
- 代码风险审查：从状态不同步、数据丢失、缓存过期、异常事件角度挑出高风险实现。

主要发现并已处理：

- 确认菜单可能因选择状态类型不同而为空。
- 菜篮子会读取当前菜单，而不是刚确认的菜单。
- 旧菜篮子勾选会继承到新菜单。
- 选菜页成员没有接入家庭成员。
- 反馈页承诺“发给我们”，但实际只保存在本机。
- 首页重复加入推荐会叠加份数。
- 自定义菜步骤图可能错配。
- 旧家庭缓存会长期显示。

## 下一轮需求建议

1. 真的提交反馈
   - 现在“提个想法”只是本机记录。
   - 如果要让开发者收到，需要新增后端接口和列表查看能力。

2. 家庭菜单真正多人同步
   - 当前家庭成员能用于“谁点菜”的归属展示。
   - 菜单本身仍主要存在本机。
   - 下一步可以把当前菜单、确认菜单、菜篮子状态放到家庭空间里。

3. 确认菜单后的再次编辑
   - 当前确认后会清空当前菜单。
   - 如果用户想回头改刚确认的菜单，需要从菜单历史里复用。
   - 可以在确认成功页增加“再改一下”入口。

4. 菜品图片体验
   - 已有默认占位图和用户上传。
   - 下一步可以补图片裁剪预览、删除图片、重新使用默认图。

5. 上线前真机验收
   - 手机号授权必须用正式 AppID 的预览/真机确认。
   - 需要验证添加手机号、创建家庭、加入家庭、确认菜单、查看菜篮子五条链路。

## 当前验收结论

这版已经从“能跑的模板改造”推进到“主要家庭菜单流程可用”。最大一批用户会直接踩到的流程坑已经修掉：确认断链、旧状态误导、重复加入、菜篮子错源、步骤图错配、家庭缓存假状态。

剩余最大产品缺口是：家庭多人协作还没有真正把菜单同步到云端；反馈也还没有真的发到服务端。这两件事是下一轮最值得做的能力。
